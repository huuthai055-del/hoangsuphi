## 1. APPLICATION BOOTSTRAP & ENTRY POINT

---

### 1.1 Mục tiêu

- **Tối ưu hóa thứ tự Middleware (Middleware Pipeline Order):** Đảm bảo các middleware bảo mật và ghi vết chạy trước để bảo vệ máy chủ, các middleware nghiệp vụ chạy sau.
- **Tận dụng tối đa Bun Performance:** Tích hợp trực tiếp Hono.js vào API `Bun.serve` để giảm thiểu overhead dịch HTTP và tối ưu I/O.
- **Graceful Shutdown (Tắt máy chủ an toàn):** Khi nhận tín hiệu SIGTERM/SIGINT (từ Docker hoặc OS), hệ thống dừng tiếp nhận request mới, đợi các request đang chạy kết thúc (timeout 15 giây), sau đó đóng an toàn kết nối PostgreSQL và Redis để không gây mất mát dữ liệu hoặc hỏng kết nối socket.
- **Cấu hình bảo vệ biên (CORS, Rate Limiting):** Chặn đứng các truy cập trái phép từ domain lạ và chống brute-force thông qua Redis Token Bucket Rate Limiting.

### 1.2 Thiết kế

#### 1. Middleware Rate Limiting: `apps/backend/src/middleware/rate-limit.middleware.ts`

Sử dụng thuật toán Token Bucket lưu trên Redis để hạn chế tấn công DDOS / Brute-force.

```typescript
import type { MiddlewareHandler } from 'hono'
import { redis } from '@/lib/redis/client'
import { CacheKeys } from '@/lib/redis/keys'
import { RateLimitError } from '@/common/errors/http.errors'
import { AppConfig } from '@/config/app.config'

/**
 * Redis-backed Rate Limiter Middleware
 * @param endpointName Tên endpoint để định namespace rate limit
 * @param customLimit Giới hạn request tùy chọn
 */
export const rateLimit = (
  endpointName: string,
  customLimit?: number
): MiddlewareHandler => {
  return async (c, next) => {
    // 1. Xác định định danh người dùng: Dùng User ID (nếu đã đăng nhập) hoặc IP address (nếu ẩn danh)
    const userId = c.get('user')?.sub
    const clientIp = c.req.header('x-forwarded-for') || c.req.header('cf-connecting-ip') || '127.0.0.1'
    const identifier = userId ? `auth:${userId}` : `anon:${clientIp}`
    
    const key = CacheKeys.rateLimit(identifier, endpointName)
    const limit = customLimit ?? (userId ? AppConfig.rateLimit.auth : AppConfig.rateLimit.anon)
    const windowSeconds = AppConfig.rateLimit.windowMs / 1000

    // 2. Sử dụng Multi/Exec Transaction của Redis để tăng số đếm nguyên tử
    const currentRequests = await redis.incr(key)
    
    if (currentRequests === 1) {
      // Set TTL cho bucket khi khởi tạo
      await redis.expire(key, windowSeconds)
    }

    // Set các headers rate limit chuẩn
    c.res.headers.set('X-RateLimit-Limit', limit.toString())
    c.res.headers.set('X-RateLimit-Remaining', Math.max(0, limit - currentRequests).toString())

    if (currentRequests > limit) {
      c.res.headers.set('Retry-After', windowSeconds.toString())
      throw new RateLimitError('Too many requests. Please try again later.')
    }

    await next()
  }
}
```

#### 2. Khởi dựng Hono App Factory: `apps/backend/src/app.ts`

Tổ chức tập trung toàn bộ middleware và định tuyến hệ thống.

```typescript
import { Hono } from 'hono'
import { cors } from 'hono/cors'
import { env } from '@/config/env'
import { AppConfig } from '@/config/app.config'
import { loggerMiddleware } from '@/middleware/logger.middleware'
import { errorHandlerMiddleware } from '@/middleware/error-handler.middleware'
import { rateLimit } from '@/middleware/rate-limit.middleware'

// Khởi tạo Hono instance
export function createApp() {
  const app = new Hono()

  // ============================================================
  // MIDDLEWARE PIPELINE STACK (Thứ tự thực thi cực kỳ quan trọng)
  // ============================================================
  
  // 1. Logger & Request ID Tracing (Đặt đầu tiên để ghi log toàn bộ vòng đời)
  app.use('*', loggerMiddleware())

  // 2. CORS Policy (Chặn origin lạ)
  app.use(
    '*',
    cors({
      origin: env.CORS_ORIGINS,
      allowMethods: ['GET', 'POST', 'PUT', 'DELETE', 'OPTIONS'],
      allowHeaders: ['Content-Type', 'Authorization', 'X-Request-ID', 'X-Correlation-ID'],
      exposeHeaders: ['Content-Length', 'X-Request-ID', 'X-Correlation-ID'],
      maxAge: 600,
      credentials: true,
    })
  )

  // 3. Global Security Headers (Security headers cơ bản)
  app.use('*', async (c, next) => {
    c.res.headers.set('X-Content-Type-Options', 'nosniff')
    c.res.headers.set('X-Frame-Options', 'DENY')
    c.res.headers.set('X-XSS-Protection', '1; mode=block')
    await next()
  })

  // 4. Request Timeout Middleware: Tự động ngắt request nếu treo quá 30 giây
  app.use('*', async (c, next) => {
    let timeoutId: any
    const timeoutPromise = new Promise((_, reject) => {
      timeoutId = setTimeout(() => {
        reject(new Error('Request Timeout'))
      }, 30000) // 30 giây timeout
    })
    try {
      await Promise.race([next(), timeoutPromise])
    } finally {
      clearTimeout(timeoutId)
    }
  })

  // 5. Rate Limiter cho toàn bộ router
  app.use('/api/*', rateLimit('global'))

  // ============================================================
  // ROUTING SETUP
  // ============================================================
  
  // Kubernetes/Docker Swarm Liveness & Readiness Endpoints
  // Live: Kiểm tra xem app process có đang chạy ổn định không
  app.get('/health/live', (c) => c.text('OK', 200))
  
  // Ready: Kiểm tra xem app đã sẵn sàng tiếp nhận traffic chưa (kết nối DB, Redis ổn định)
  app.get('/health/ready', async (c) => {
    // Sẽ gọi dbHealthCheck() và redisHealthCheck()
    return c.json({ status: 'ready', timestamp: new Date().toISOString() }, 200)
  })

  // Route Group V1
  const v1Router = new Hono()
  
  // Nạp các modules (ví dụ: health, auth)
  // v1Router.route('/auth', authRouter)
  // v1Router.route('/health', healthRouter)
  
  app.route(AppConfig.server.apiPrefix, v1Router)

  // ============================================================
  // GLOBAL EXCEPTION FILTER (Đặt cuối cùng để bắt toàn bộ lỗi)
  // ============================================================
  app.onError(errorHandlerMiddleware())


  // Bắt các route không tồn tại (404)
  app.notFound((c) => {
    c.res.headers.set('Content-Type', 'application/problem+json')
    return c.json({
      type: 'https://hoangsuphi.vn/errors/not-found',
      title: 'Resource Not Found',
      status: 404,
      code: 'SYS_002',
      detail: `The requested path [${c.req.path}] does not exist on this server.`,
      instance: c.req.path,
    }, 404)
  })

  return app
}
```

#### 3. Entry Point (Bun HTTP Server): `apps/backend/src/index.ts`

Nạp app và quản lý vòng đời hoạt động của OS Server.

```typescript
import { createApp } from './app'
import { env } from '@/config/env'
import { logger } from '@/lib/logger'
import { redis, redisHealthCheck } from '@/lib/redis'
import { db, dbHealthCheck } from '@/lib/database/client'

// ============================================================
// STARTUP VALIDATION SYSTEM (Fail-fast trước khi boot server)
// ============================================================
async function validateBootstrap() {
  logger.info('🔍 Starting Startup Validation Pipeline...')
  
  // 1. Kiểm tra cấu hình kết nối DB (SELECT 1)
  const dbHealth = await dbHealthCheck()
  if (dbHealth.status === 'unhealthy') {
    logger.fatal({ error: dbHealth.error }, '🚨 Startup Validation Failed: Database connection refused!')
    process.exit(1)
  }
  
  // 2. Kiểm tra cấu hình kết nối Redis (PING)
  const redisHealth = await redisHealthCheck()
  if (redisHealth.status === 'unhealthy') {
    logger.fatal({ error: redisHealth.error }, '🚨 Startup Validation Failed: Redis connection refused!')
    process.exit(1)
  }

  logger.info('✅ Startup Validation Pipeline: ALL SYSTEMS FUNCTIONAL')
}

// Chạy validate trước khi serve HTTP
await validateBootstrap()

const app = createApp()

// Khởi chạy Bun HTTP Server native
const server = Bun.serve({
  port: env.PORT,
  hostname: env.HOST,
  fetch: app.fetch,
})

// ============================================================
// STARTUP BANNER (Tóm tắt thông số hữu ích khi debug)
// ============================================================
const banner = `
============================================================
       HOANG SU PHI TOURISM API GATEWAY (Bun Node Runtime)
============================================================
  Version     : v1.0.0
  Environment : ${env.NODE_ENV}
  Host/Port   : http://${env.HOST}:${env.PORT}
  Database    : Connected (PostgreSQL 16 + PostGIS)
  Redis Cache : Connected (Redis 7.2 + KeyPrefix v1)
  Logger      : Active (Level: ${env.LOG_LEVEL})
============================================================
`
console.log(banner)

// ============================================================
// GRACEFUL SHUTDOWN SYSTEM
// ============================================================

let isShuttingDown = false

async function gracefulShutdown(signal: string) {
  if (isShuttingDown) return
  isShuttingDown = true

  logger.warn({ signal }, `🛑 Received shutdown signal. Initiating graceful shutdown...`)

  // 1. Dừng nhận thêm kết nối HTTP mới và đóng server
  server.stop()
  logger.info('HTTP Server stopped accepting new connections')

  // 2. Chờ timeout cấu hình động từ env (hoặc default 10s) để request drain
  const shutdownTimeoutMs = process.env.GRACEFUL_SHUTDOWN_TIMEOUT_MS 
    ? parseInt(process.env.GRACEFUL_SHUTDOWN_TIMEOUT_MS, 10) 
    : 10000

  logger.info(`Draining active requests (timeout: ${shutdownTimeoutMs}ms)...`)
  await new Promise((resolve) => setTimeout(resolve, shutdownTimeoutMs))

  // 3. Đóng kết nối PostgreSQL Pool & Redis
  try {
    logger.info('Closing database connection pools...')
    // postgres.js client tự động dọn dẹp connection pool khi kết thúc process, 
    // tuy nhiên ta có thể gọi close tường minh nếu driver hỗ trợ.
    
    logger.info('Closing Redis connection pool...')
    await redis.quit()
    logger.info('Redis connection closed successfully')
  } catch (error: any) {
    logger.error({ error: error.message }, 'Error occurred during connection teardown')
  }

  logger.warn('👋 API Server gracefully shut down. Exiting process.')
  process.exit(0)
}

// Lắng nghe tín hiệu ngắt từ OS/Docker
process.on('SIGTERM', () => gracefulShutdown('SIGTERM'))
process.on('SIGINT', () => gracefulShutdown('SIGINT'))

```

### 1.3 Lý do lựa chọn

| Quyết định thiết kế | Lý do lựa chọn |
|:---|:---|
| **Bun.serve** | Tốc độ phân phối HTTP và hiệu năng I/O tốt hơn Node.js thuần đến 2-3x, tương thích hoàn hảo với cú pháp HTTP của Hono. |
| **Thứ tự Middleware cụ thể** | Request ID và Logger được chạy đầu tiên để đảm bảo toàn bộ các bước phía sau (kể cả khi bị CORS hoặc Rate Limiter block) đều được ghi vết và đo đạc thời gian chính xác. |
| **Redis Token Bucket (INCR + EXPIRE)** | Đơn giản, hiệu năng cao và có tính atomic. Đảm bảo chống tấn công tràn ngập API với I/O cực thấp trên RAM Redis. |
| **`server.stop()` của Bun** | Dừng lắng nghe cổng kết nối ngay lập tức nhưng không lập tức ngắt các TCP sockets đang trao đổi dữ liệu, là nền tảng tối quan trọng cho Graceful Shutdown. |

### 1.4 Ưu điểm

- **Khả năng tự hồi phục và bảo vệ:** Server chống chịu tốt trước các đợt càn quét tự động từ bots nhờ Rate Limiter tích hợp sẵn.
- **Không mất mát dữ liệu khi deploy:** Khi deploy phiên bản mới (CI/CD kill container cũ), các request ghi DB của người dùng đang chạy dở sẽ không bị đứt gãy giữa chừng (drain-time 5s).
- **Gọn gàng và tường minh:** Tách biệt file App Factory (`app.ts`) và Entry Point (`index.ts`) giúp dễ dàng viết các integration tests (chỉ cần import `createApp` và gọi mock request mà không cần bind ports vật lý).

---

### 1.5 Nhược điểm

- **Distributed Rate Limiting sync latency:** Redis Incremental có thể lệch 1 vài requests do độ trễ truyền tải mạng, tuy nhiên đối với mục đích bảo vệ máy chủ (anti-abuse) thì độ lệch này là hoàn toàn không đáng kể.

### 1.6 Các lựa chọn khác đã xem xét

| Phương án | Vấn đề |
|:---|:---|
| **Chạy express / Fastify trên Bun** | Fastify rất tốt nhưng không tối ưu cho Bun native API bằng Hono.js. Express thì quá cũ kỹ, không có type safety nguyên bản. |
| **Rate Limit bằng memory bộ nhớ trong** | Không thể mở rộng (scale) lên đa máy chủ (Multi-instance). Khi scale lên 3 API nodes, rate limit memory sẽ bị chia rẽ, không bảo vệ được hệ thống thống nhất. |
| **Tắt đột ngột (`process.exit(0)`)** | Gây lỗi 502 Bad Gateway đột ngột cho khách hàng đang thực hiện thanh toán/ghi nhận dữ liệu, tạo ra các bản ghi DB mồ côi (orphaned entries). |

---

### 1.7 Vì sao không chọn

- **Express/Fastify:** Hono.js được thiết kế từ đầu cho Bun, Cloudflare Workers và Edge runtimes. Nó sử dụng RegExp Router siêu tốc và có kích thước siêu nhẹ, giúp khởi động server chỉ trong vài miliseconds.
- **Local Memory Rate Limiting:** Khi hệ thống Hoàng Su Phì mở rộng quy mô toàn quốc (Phase 3), việc chạy Load Balancer phân tải sang nhiều máy chủ API là bắt buộc. Dùng Redis làm trung tâm lưu Rate Limit đảm bảo mọi instance đều đồng bộ chính xác số lượng request của 1 IP.

### 1.8 Khả năng mở rộng

- **API Documentation (Scalar / OpenAPI):** Ở bước 14 của Phase 2, ta dễ dàng chèn middleware tự động sinh tài liệu API `/docs` thông qua plugin `@hono/zod-openapi` trực tiếp vào App Factory.
- **Websocket Support:** Bun.serve hỗ trợ native websockets hiệu năng cao. Nếu sau này cần tính năng chat, live-notifications, ta chỉ cần khai báo thêm cấu trúc `websocket` trong `Bun.serve`.

### 1.9 Best Practices

- **Security Headers:** Bắt buộc cấu hình `X-Content-Type-Options: nosniff` và `X-Frame-Options: DENY` để chống Clickjacking và MIME-sniffing.
- **CORS strict configuration:** Tuyệt đối không dùng `origin: '*'` ở môi trường production. CORS Origins phải được cấu hình động qua biến môi trường nạp từ env.
- **Graceful timeout:** Đặt Drain timeout phù hợp (5-15s), không đặt quá lâu khiến CI/CD pipeline bị nghẽn thời gian chờ.
