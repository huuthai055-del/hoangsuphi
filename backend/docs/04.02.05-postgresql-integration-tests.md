### 1. Test Architecture Overview

The integration suite tests the complete horizontal execution path without mock layers:

```
HTTP GET /api/v1/nearby
  ↓ (Hono Route & Zod Validation)
NearbyController
  ↓ (Applies bounds & maps parameters)
NearbySearchService
  ↓ (Query Canonicalization & Keyset Cryptographic Signature)
DrizzleNearbyRepository
  ↓ (Set-based SQL Execution with PostGIS Geography)
PostgreSQL & PostGIS (Real Test Instance)
```

### 3. Test Cases Verified

The integration suite contains **14 comprehensive test cases** organized into distinct groups:

#### Group A: End-to-End Baseline
* **A1. Minimum Request:** Validates that `GET /api/v1/nearby?lat=22.7844&lng=104.6644` returns HTTP 200, matching expected JSON structure and defaults (5000m radius, 20 limit).
* **A2. Zero Results:** Verifies empty dataset (`data: []`) when search coordinates are far from any data (e.g., USA).

#### Group B: Spatial & Radius Limits
* **B1. Radius Exclusions:** Confirms entities within radius are returned (10m, 370m, 2.6km) while the 7.7km place is completely omitted.

#### Group C: Entity Type Projection
* **C1. Type Dispatching:** Tests parsing of parameter `types` (CSV format) and projects each database record type accurately to `TOURIST_PLACE`, `ATTRACTION`, `UTILITY`, and `BUSINESS` respectively.

#### Group D: Visibility Rules
* **D1. Enforcement:** Guarantees soft-deleted entities, inactive status records, entities within deleted regions, and businesses with inactive business types are automatically hidden.

#### Group E & F: Region & Category Filtering
* **E1. Region Strict Match:** Assures region-based lookup returns matches from the specific region and correctly filters sibling regions.
* **F1. Category Mapping & Exclusions:** Confirms `categoryId` filter restricts results for `ATTRACTION` (including `attractionVeryClose` and excluding `attractionDifferentCategory`) and `BUSINESS` (including `businessWithin5kmActiveType` and excluding `businessDifferentType`).

#### Group G: Review Rating Aggregation
* **G1. Core Aggregations:** Verifies set-based average rating and review counts are aggregated accurately (excluding pending, rejected, or deleted reviews).

#### Group H: Global Ordering
* **H1. Spheroid Distance & UUID Sort:** Validates that entities are sorted by distance ASC. When distances match exactly, the sorting fallback rules are enforced: `entityTypeRank` ASC (Place [1] → Attraction [2] → Business [3]) followed by `UUID` ASC (validating ordering sequence of `placeVeryClose` < `placeEqualDistance1` < `placeEqualDistance2`).

#### Group I: Keyset Pagination
* **I1. Keyset Navigation:** Fetches baseline of all items, then traverses page-by-page recursively using `limit=2` and `nextCursor` until `hasMore` is false. Verifies total count, IDs match baseline exactly, no duplicates, and final page has `nextCursor=null`.

#### Group J: Keyset Security & Tamper Proofing
* **J1. Signature Validation:** Ensures modifying query parameters (e.g., radius, coordinates) with an existing cursor or tampering with the HMAC signature payload returns HTTP 400.

#### Group K, L & M: API Error & Contract
* **K1. Input Validation:** Verifies coordinate out-of-bounds, invalid radius values (min 100m, max 50000m), and limit ranges trigger HTTP 400.
* **L1. Response Shape:** Validates public envelope `{ data, meta, error: null }` schema.
* **M1. Problem Details:** Confirms RFC 7807 formatted error shapes on exceptions.

### 4. Running the Tests Locally

To run the integration tests locally, you need a dedicated test database (e.g., `hoangsuphi_test` with PostGIS enabled).

```bash
# Configure the test database environment variable and run:
$env:SEARCH_TEST_DATABASE_URL="postgres://postgres:postgres@localhost:5432/hoangsuphi_test"
bun test src/modules/nearby
```

If `SEARCH_TEST_DATABASE_URL` is not set, the suite is cleanly skipped.
