## 4. API manifest

| Method | Endpoint | Query | Result | Cache |
| :--- | :--- | :--- | :--- | :--- |
| GET | `/api/v1/harvest-status` | strict `limit` (1–50, default 20), signed `cursor` | one current public update per eligible region | `no-store` |
| GET | `/api/v1/harvest-status/regions/:slug` | strict lowercase ASCII kebab slug, `limit`, signed region-bound `cursor` | region, global current and public timeline | `no-store` |

Unknown/duplicate query parameters, invalid limits, invalid slugs and tampered/mismatched cursors use the existing RFC 7807 error pipeline. Missing, deleted or wrong-level regions share the generic `HARVEST_REGION_NOT_FOUND_OR_UNAVAILABLE` 404 response.

## 5. Current-state semantics

- SQL filters `PUBLISHED` and `deleted_at IS NULL` before ranking.
- `ROW_NUMBER()` partitions by region and orders by `observed_at DESC, published_at DESC, id DESC`.
- Only non-deleted level 3/4 regions are eligible. The locked Region schema has no separate active/status column, so this is the complete public eligibility contract supported by the actual schema.
- Global page ordering is `observed_at DESC, region_name ASC, region_id ASC`; the cursor stores every ordering key.

## 6. Timeline semantics

- Timeline ordering is `observed_at DESC, published_at DESC, id DESC`.
- The cursor is HMAC-SHA256 signed and bound to endpoint scope, region ID, limit and ordering version.
- Global current is selected independently from the cursor page in the same SQL statement, so it remains correct on later pages.
- A valid region with no public update returns `200`, `current: null` and an empty timeline.

## 8. Media audit

The correlated set-based Media projection accepts only `READY`, `IMAGE`, non-deleted rows with `owner_type = HARVEST_UPDATE` and `owner_id` equal to the projected update. It orders by `created_at ASC, id ASC`, caps legacy/inconsistent data at eight items and prefers `large`, then `medium`, then `original` variants. Internal provider/key data exists only inside the repository-to-storage boundary; the public mapper returns URL, dimensions, alt text and variant, never storage key, uploader or ownership metadata.

## 9. Query architecture

- Current endpoint: one PostgreSQL query using CTE, window function, join and correlated Media JSON aggregation.
- Region endpoint: one eligibility query plus one timeline/current/media query.
- Query count is constant (1 and 2 respectively) and does not scale with regions, updates or Media items.
- No domain hydration, admin-service read, application grouping, OFFSET, per-row repository loop or HTTP call to Region/Media exists.

## 10. Security audit

- Zod DTOs reject unknown/duplicate parameters, loose numbers, invalid slug characters and oversized cursors.
- All SQL values are Drizzle parameter bindings; injection payload tests return validation errors.
- Region state is hidden behind one generic 404 contract.
- Public update/Media DTOs exclude lifecycle, actor, audit, ownership and storage fields.
- Cursor version, canonical encoding, key ID, context fingerprint, dates, UUIDs and HMAC are validated; invalid cursors never fall back to page one.
- Public and protected admin routers remain separate.

## 11. Read-only audit

Public repository source contains SELECT/CTE projections only. Integration tests snapshot Harvest rows and Media ownership before and after concurrent public GETs and prove no INSERT, UPDATE or DELETE side effect. The two public GET routes bypass the Redis-backed global limiter because the approved Phase 4.8 contract forbids every Redis read/write for this read model. No event, queue, cron or cache is used.

## 12. Permission regression

- Public GET routes require no authentication and do not read user/session/profile state.
- Admin create, patch, publish and archive still require authentication and `harvest:write`.
- Anonymous admin mutation remains 401; insufficient permission remains forbidden.
- Media ownership is still assigned only by the server-side Harvest port.
