## 1. INPUT VALIDATION & DTO STRATEGY

---

### 1.1 Mục tiêu

- **Bảo vệ biên API (Securing the API Boundaries):** Đảm bảo không có dữ liệu sai cấu trúc hoặc độc hại có thể đi sâu vào tầng Service hay Database layer (chặn đứng SQL Injection cơ bản, XSS, Overflow).
- **Type-Safety End-to-End:** Suy luận tự động (Type inference) các kiểu dữ liệu DTO từ Zod schema sang static types của TypeScript, giảm thiểu việc trùng lặp khai báo Interface.
- **Phản hồi lỗi chi tiết (Field-level Error Reporting):** Khi validate lỗi, tự động trả về chi tiết chính xác trường nào bị sai và lý do (reason), tương thích hoàn toàn với schema `invalidParams` của RFC 7807 (tài liệu 02.07).
- **Phân tách rõ ràng (DTO vs Domain Model):** Input client gửi lên (DTO) và cấu trúc dữ liệu lưu trong DB (Domain Model) là khác nhau. Bắt buộc map qua lại rõ ràng, ngăn ngừa Auto-binding vulnerability (lỗ hổng tự động gán dữ liệu không mong muốn).

---

### 1.2 Thiết kế

Chúng ta xây dựng hệ thống validate thông qua thư viện `zod` và viết một Custom Validation Middleware cho Hono.js để kiểm soát 3 luồng dữ liệu: `body` (JSON), `query` (URL Search Params) và `param` (Route Path Params).

#### 1. Custom Validation Middleware: `apps/backend/src/middleware/validate.middleware.ts`

```typescript
import type { MiddlewareHandler } from 'hono'
import { ZodSchema, ZodError } from 'zod'
import { ValidationError } from '@/common/errors/http.errors'

type ValidationTarget = 'json' | 'query' | 'param'

/**
 * Zod Validation Middleware cho Hono
 * @param target Nguồn dữ liệu cần validate ('json' | 'query' | 'param')
 * @param schema Zod Schema tương ứng
 */
export const validate = (
  target: ValidationTarget,
  schema: ZodSchema
): MiddlewareHandler => {
  return async (c, next) => {
    let data: unknown

    try {
      // 1. Trích xuất dữ liệu dựa theo Target
      if (target === 'json') {
        // Hỗ trợ kiểm tra nếu không có body (hoặc JSON rỗng)
        data = await c.req.json().catch(() => ({}))
      } else if (target === 'query') {
        data = c.req.query()
      } else if (target === 'param') {
        data = c.req.param()
      }

      // 2. Validate bằng Zod
      const parsed = await schema.safeParseAsync(data)

      if (!parsed.success) {
        // 3. Chuyển đổi ZodError sang invalidParams định dạng của RFC 7807
        const invalidParams = parsed.error.issues.map((issue) => ({
          name: issue.path.join('.'),
          reason: issue.message,
        }))

        // Throw lỗi ValidationError đã được định nghĩa tại 02.07
        throw new ValidationError('Request validation failed', invalidParams)
      }

      // 4. Gán ngược lại dữ liệu đã parse thành công (đã strip các key lạ) vào context
      c.req.addValidatedData(target, parsed.data)
      
      await next()
    } catch (err) {
      if (err instanceof ZodError) {
        const invalidParams = err.issues.map((issue) => ({
          name: issue.path.join('.'),
          reason: issue.message,
        }))
        throw new ValidationError('Request validation failed', invalidParams)
      }
      throw err // Để Global Error Handler xử lý các lỗi khác
    }
  }
}
```

#### 2. Định nghĩa DTOs dùng chung: `apps/backend/src/common/dtos/pagination.dto.ts`

```typescript
import { z } from 'zod'

// Cursor-based Pagination DTO dùng chung cho toàn bộ API List
export const PaginationQuerySchema = z.object({
  cursor: z.string().uuid('Cursor must be a valid UUIDv7').optional(),
  limit: z
    .coerce
    .number()
    .int()
    .min(1, 'Limit must be at least 1')
    .max(50, 'Limit cannot exceed 50')
    .default(20),
})

export type PaginationQueryDto = z.infer<typeof PaginationQuerySchema>
```

#### 4. Ví dụ định nghĩa DTO trong một Module: `apps/backend/src/modules/auth/auth.dto.ts`

```typescript
import { z } from 'zod'

// ─── Login Request DTO ───────────────────────────────────────────────────────
export const LoginRequestSchema = z.object({
  email: z
    .string({ required_error: 'Email is required' })
    .email('Invalid email address format')
    .max(255, 'Email cannot exceed 255 characters')
    .trim()
    .toLowerCase(),
  password: z
    .string({ required_error: 'Password is required' })
    .min(8, 'Password must be at least 8 characters')
    .max(100, 'Password cannot exceed 100 characters'),
})

// Trích xuất static types tự động cho Service layer tiêu thụ
export type LoginRequestDto = z.infer<typeof LoginRequestSchema>

// ─── Token Response DTO (Serialization / Output DTO) ────────────────────────
export const TokenResponseSchema = z.object({
  accessToken: z.string(),
  refreshToken: z.string(),
  expiresIn: z.number(),
})

export type TokenResponseDto = z.infer<typeof TokenResponseSchema>
```

### 1.3 Lý do lựa chọn

| Quyết định thiết kế | Lý do lựa chọn |
|:---|:---|
| **Zod** | Là thư viện schema validation tốt nhất hiện tại cho TypeScript, hỗ trợ type inference trực quan mà không cần dùng các decorators rườm rà (như `class-validator` vốn gây chậm thời gian startup và biên dịch). |
| **`safeParseAsync`** | Chạy validate bất đồng bộ. Điều này quan trọng khi cần thực hiện validate nâng cao có truy vấn DB (ví dụ check email trùng lặp trực tiếp từ DB ngay tại tầng schema validation nếu cần). |
| **`addValidatedData`** | Đây là hàm built-in của Hono.js. Nó giúp bảo vệ an toàn: dữ liệu truyền vào Service đã được strip sạch các trường rác (đề phòng lỗ hổng Mass Assignment). |
| **Co-location DTOs** | File `[module].dto.ts` nằm ngay trong thư mục module giúp dễ dàng chỉnh sửa, review, và refactor. |

---

### 1.4 Ưu điểm

- **Loại bỏ dữ liệu rác (Strict Stripping):** Mọi key lạ nằm ngoài Schema gửi lên từ client đều bị Zod loại bỏ, ngăn chặn kẻ tấn công lợi dụng ghi đè các cột nhạy cảm (như `is_admin = true`, `role = 'admin'`).
- **Phản hồi chuẩn hóa tự động:** Developer không cần viết code xử lý lỗi validate, middleware tự bắt và map sang schema RFC 7807 lỗi `VAL_001`.
- **An toàn kiểu dữ liệu (Type Safety):** Service layer nhận dữ liệu hoàn toàn chắc chắn về mặt kiểu dữ liệu, không lo `undefined` hay sai định dạng.

---

### 1.5 Nhược điểm

- **Khởi tạo Zod Schema tốn công:** Cần viết chi tiết cho từng API endpoint. Tuy nhiên đây là cái giá xứng đáng để có hệ thống bảo mật cao và an toàn kiểu dữ liệu.

---

### 1.6 Các lựa chọn khác đã xem xét

| Phương án | Vấn đề |
|:---|:---|
| **class-validator / class-transformer** | Rất phổ biến ở NestJS. Gây chậm runtime do phụ thuộc vào metadata reflection (Reflect-metadata), tốn boilerplate class và cú pháp TypeScript Decorator không thân thiện bằng Zod. |
| **Joi** | Viết bằng Javascript thuần, tính năng Type Inference sang TypeScript rất kém, đòi hỏi khai báo interface thủ công lần hai. |
| **Ajv (JSON Schema)** | Nhanh nhất về mặt tốc độ thực thi, nhưng cú pháp khai báo JSON Schema thô sơ, cực kỳ khó viết và khó bảo trì bằng tay. |

---

### 1.7 Vì sao không chọn

- **Class-validator:** NestJS-style decorators. Hono.js và Bun hướng tới sự tối giản, hiệu năng cao và type-safe nguyên bản. Dùng decorator vừa tăng kích thước bundle vừa tạo overhead xử lý tại runtime không đáng có. Zod cung cấp cú pháp khai báo hàm (functional declaration) hiện đại và an toàn kiểu tĩnh tốt hơn.

---

### 1.8 Khả năng mở rộng

- **Shared DTO Packages:** Khi dự án lớn lên (Phase 5+), file `[module].dto.ts` có thể dễ dàng di chuyển ra ngoài thư mục `packages/shared-validators` để chia sẻ dùng chung cho cả Frontend (Next.js) validate form trên trình duyệt, không cần viết lại logic validate.
- **Custom Zod Refinements:** Có thể viết custom validators bằng Zod (ví dụ: validate biển số xe Hà Giang, validate số điện thoại Việt Nam chuẩn) và tái sử dụng ở mọi DTOs.

---

### 1.9 Best Practices

- **Luôn sử dụng `.trim()` và `.toLowerCase()`:** Đối với các trường như email, username để đảm bảo tính nhất quán dữ liệu ở DB và tránh lỗi duplicate không mong muốn.
- **Sử dụng `.coerce` hợp lý:** Khi validate dữ liệu từ `query` hoặc `param` (vốn mặc định là string từ URL), dùng `.coerce.number()` để Zod tự chuyển sang number trước khi validate.
- **Strict schemas:** Với các API đầu vào quan trọng (như tạo mới, cập nhật), nên dùng `.strict()` để chặn tuyệt đối nếu client gửi thừa tham số.
