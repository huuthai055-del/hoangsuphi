## 1. DATABASE CONNECTION LAYER

---

### 1.1 Mục tiêu

- **Tối ưu hóa Connection Pool:** Quản lý kết nối PostgreSQL hiệu quả, chống cạn kiệt tài nguyên (connection starvation) và tự động dọn dẹp kết nối nhàn rỗi (idle connection timeout).
- **Hỗ trợ các kiểu dữ liệu nâng cao:** Đảm bảo Drizzle ORM tương thích và hỗ trợ tốt kiểu dữ liệu địa lý (`GEOGRAPHY` của PostGIS) và phân cấp cây (`ltree` của PostgreSQL).
- **Type-safe hoàn toàn:** Hỗ trợ suy luận kiểu (type inference) đầy đủ từ tầng Database lên tầng Service mà không cần viết thủ công các Type/Interface định nghĩa thực thể.
- **Giám sát truy vấn (Query Logging):** Tích hợp Pino logger để ghi vết (audit) và đo đạc thời gian chạy của truy vấn SQL trong môi trường phát triển (development), tắt ở môi trường sản xuất (production) để tối ưu hiệu năng.
- **Sẵn sàng cho Read-Replicas:** Thiết kế lớp truy xuất dữ liệu có khả năng phân luồng ghi (Primary) và đọc (Replicas) trong tương lai.

---

### 1.2 Thiết kế

Chúng ta sử dụng thư viện driver `postgres` (Postgres.js) - driver được đánh giá nhanh nhất cho Node.js/Bun hiện tại, kết hợp cùng `drizzle-orm`.

#### 1. `apps/backend/src/lib/database/client.ts`

Khởi tạo kết nối PostgreSQL với Pool và Drizzle.

```typescript
import { drizzle } from 'drizzle-orm/postgres-js'
import postgres from 'postgres'
import { env, isDev } from '@/config/env'
import { logger } from '@/lib/logger'
import * as schema from './schema'

// Định nghĩa log format cho Drizzle Query Logger
class DrizzlePinoLogger {
  logQuery(query: string, params: unknown[]): void {
    if (isDev) {
      logger.debug({ query, params }, '🔌 Database Query')
    }
  }
}

// Cấu hình postgres client (driver connection pool)
const queryClient = postgres(env.DATABASE_URL, {
  max: env.DATABASE_POOL_MAX,
  idle_timeout: env.DATABASE_IDLE_TIMEOUT_MS / 1000, // đổi sang giây
  connect_timeout: env.DATABASE_CONNECT_TIMEOUT_MS / 1000,
  // Tự động retry khi mất kết nối tạm thời
  max_lifecycle_seconds: 1800, // 30 phút tự refresh connection
  onparameter: (key, value) => {
    // Tránh log thông tin nhạy cảm
  }
})

// Khởi tạo Drizzle Instance
export const db = drizzle(queryClient, {
  schema,
  logger: isDev ? new DrizzlePinoLogger() : false,
})

// Export type cho Database client dùng cho Dependency Injection
export type Database = typeof db

// ─── Enterprise Health Check ────────────────────────────────────────────────
// Hàm kiểm tra tình trạng kết nối DB (dùng cho healthcheck endpoint)
export async function dbHealthCheck(): Promise<{ status: 'healthy' | 'unhealthy'; latencyMs: number; error?: string }> {
  const start = performance.now()
  try {
    // Thực thi query tối giản SELECT 1
    await db.execute(postgres.sql`SELECT 1`)
    const latencyMs = Math.round(performance.now() - start)
    return { status: 'healthy', latencyMs }
  } catch (err: any) {
    logger.error({ error: err.message }, '❌ Database health check failed')
    return {
      status: 'unhealthy',
      latencyMs: Math.round(performance.now() - start),
      error: err.message,
    }
  }
}

// ─── Transaction Helper Wrapper ──────────────────────────────────────────────
// Giúp các service thực thi transaction thống nhất mà không cần quản lý raw connection
export async function runInTransaction<T>(
  callback: (tx: any) => Promise<T>
): Promise<T> {
  return db.transaction(async (tx) => {
    try {
      return await callback(tx)
    } catch (error) {
      logger.error({ error }, '🔌 Database Transaction rollback')
      throw error
    }
  })
}

```

#### 2. Định nghĩa Custom Types cho PostGIS và ltree trong Drizzle

Vì Drizzle chưa có native helper cho PostGIS `GEOGRAPHY(Point)` và PostgreSQL `ltree`, chúng ta cần tự định nghĩa custom columns để đảm bảo tính type-safe ở tầng application.

Tạo tệp `apps/backend/src/lib/database/schema/custom-types.ts`:

```typescript
import { customType } from 'drizzle-orm/pg-core'

// ─── PostGIS Point Type ──────────────────────────────────────────────────────
// Lưu trữ tọa độ GPS { lng: number, lat: number }
export interface Point {
  lng: number
  lat: number
}

export const point = customType<{ data: Point; driverData: string }>({
  dataType() {
    return 'geography(Point,4326)'
  },
  toDriver(value: Point): string {
    return `SRID=4326;POINT(${value.lng} ${value.lat})`
  },
  fromDriver(value: string): Point {
    // Chuỗi driver data có định dạng: SRID=4326;POINT(lng lat) hoặc WKB hex
    // Ta parse dạng POINT(lng lat) đơn giản
    const match = value.match(/POINT\(([^ ]+)\s+([^ ]+)\)/)
    if (!match) {
      throw new Error(`Invalid Point format from database: ${value}`)
    }
    return {
      lng: parseFloat(match[1]),
      lat: parseFloat(match[2]),
    }
  },
})

// ─── PostgreSQL ltree Type ───────────────────────────────────────────────────
// Lưu trữ đường dẫn dạng cây, ví dụ: 'vietnam.hagiang.hoangsuphi'
export const ltree = customType<{ data: string; driverData: string }>({
  dataType() {
    return 'ltree'
  },
  toDriver(value: string): string {
    // Validate ltree label format: chỉ cho phép chữ, số, dấu gạch dưới, phân tách bởi dấu chấm
    // Chuyển đổi dấu gạch ngang (nếu có) thành dấu gạch dưới theo Known Problem P3
    const normalized = value.replace(/-/g, '_')
    if (!/^[a-zA-Z0-9_]+(\.[a-zA-Z0-9_]+)*$/.test(normalized)) {
      throw new Error(`Invalid ltree format: ${value}`)
    }
    return normalized
  },
  fromDriver(value: string): string {
    return value
  },
})
```

#### 3. Ví dụ định nghĩa một phần Schema để minh họa (Sử dụng UUIDv7)

Tạo tệp `apps/backend/src/lib/database/schema/core/regions.ts`:

```typescript
import { pgTable, text, timestamp, uuid } from 'drizzle-orm/pg-core'
import { ltree, point } from '../custom-types'

export const regions = pgTable('regions', {
  id: uuid('id').primaryKey(), // Sẽ generate UUIDv7 tại Application Layer
  name: text('name').notNull(),
  slug: text('slug').notNull().unique(),
  path: ltree('path').notNull().unique(),
  gps: point('gps'),
  created_at: timestamp('created_at', { withTimezone: true }).defaultNow().notNull(),
  updated_at: timestamp('updated_at', { withTimezone: true }).defaultNow().notNull(),
  deleted_at: timestamp('deleted_at', { withTimezone: true }),
})
```

### 1.3 Lý do lựa chọn

| Quyết định thiết kế | Lý do lựa chọn |
|:---|:---|
| **Drizzle ORM** | Type-safe cực cao, tốc độ query gần tương đương SQL thuần, không có "magic abstraction layer" nặng nề như Prisma hay TypeORM. Rất dễ tích hợp custom types cho GIS và ltree. |
| **Postgres.js driver** | Thư viện kết nối nhẹ nhất và nhanh nhất hiện nay, hỗ trợ tự động chuẩn bị câu lệnh (prepared statements), tự dọn dẹp connection rác và tích hợp sẵn connection pooling mà không cần binary libs cồng kềnh. |
| **Custom Types** | Cho phép đóng gói logic parse/format tọa độ PostGIS và xử lý format `ltree` (chuyển `-` thành `_`) ngay tại DB mapping layer, giúp Service layer không phải xử lý thủ công. |

### 1.4 Ưu điểm

- **Hiệu năng vượt trội:** Không có độ trễ dịch truy vấn lớn (như Prisma engine vốn chạy bằng Rust qua gRPC).
- **Type Safety tối đa:** Type inference hoạt động từ bảng DB tới API Response (`InferSelectModel<typeof regions>`).
- **Kiểm soát tuyệt đối:** Drizzle không che giấu SQL. Câu lệnh viết thế nào sẽ sinh ra SQL như thế đó, giúp tối ưu chỉ mục (Index) hiệu quả.
- **Database-centric features support:** Dễ dàng chạy raw SQL hoặc sử dụng Drizzle Query Builder tùy theo độ phức tạp của bài toán.

---

### 1.5 Nhược điểm

- **Khởi tạo schema ban đầu tốn sức:** Drizzle đòi hỏi tự định nghĩa schema chi tiết bằng TypeScript, tốn code hơn so với việc tự động sinh schema từ DB của Prisma.
- **Database Migrations phức tạp hơn:** Việc quản lý migrations đòi hỏi chạy CLI của Drizzle (`drizzle-kit`), đôi khi cần can thiệp file SQL thủ công đối với các cấu trúc phức tạp như phân mảnh bảng (Partitioning).

---

### 1.6 Các lựa chọn khác đã xem xét

| Phương án | Vấn đề |
|:---|:---|
| **Prisma ORM** | Gặp nhiều vấn đề về hiệu năng và tốn bộ nhớ khi kết nối pool do chạy Prisma Engine (Rust client). Hỗ trợ PostGIS và ltree rất hạn chế, thường phải qua raw SQL. |
| **Kysely** | Query builder rất tốt và type-safe, tuy nhiên thiếu tính năng tự sinh Migration (drizzle-kit) và mapping quan hệ tự động (Relations API) dẫn đến tốn thời gian code boilerplate. |
| **pg (node-postgres) + raw SQL** | Tốc độ nhanh nhất nhưng mất đi tính type-safe và tốn thời gian map dữ liệu thủ công. |

---

### 1.7 Vì sao không chọn

- **Prisma:** Đối với ứng dụng cần xử lý spatial data chuyên sâu (PostGIS nearby search, distance calculation) và phân cấp hành chính (`ltree`), Prisma bắt buộc dev phải viết rất nhiều raw query bypass ORM. Điều này phủ nhận ưu điểm lớn nhất của Prisma và giữ lại toàn bộ nhược điểm về hiệu năng kết nối.
- **Kysely:** Rất thích hợp làm core engine, nhưng vì dự án cần go-live nhanh mà vẫn bảo toàn cấu trúc Enterprise, Drizzle ORM đem lại sự cân bằng hoàn hảo nhất giữa DX (Developer Experience), tốc độ, và tính an toàn.

---

### 1.8 Khả năng mở rộng

- **Read-Replicas Routing (Scale Read):** Khi traffic đọc tăng cao (Phase 7), ta có thể dễ dàng tách kết nối của Drizzle ra 2 clients:
  ```typescript
  const writeDb = drizzle(postgres(env.DATABASE_URL))
  const readDb = drizzle(postgres(env.DATABASE_READ_URL))
  ```
  Nhờ Repository Pattern (02.01), Services không cần đổi code, chỉ cần điều hướng gọi `readDb` hoặc `writeDb` ở tầng Repository.
- **PgBouncer compatibility:** Postgres.js hỗ trợ chế độ `prepared statements: false` khi cần chạy qua Transaction mode của PgBouncer.

---

### 1.9 Best Practices

- **Luôn sử dụng UTC TIMESTAMPTZ:** Toàn bộ timestamp lưu trữ ở DB và mapping ở Drizzle phải dùng `timestamp('...', { withTimezone: true })`.
- **Soft Delete filter:** Tầng Repository chịu trách nhiệm tự động thêm điều kiện `deleted_at IS NULL` cho mọi truy vấn trừ khi có nhu cầu đặc biệt lấy dữ liệu đã xóa.
- **Transaction isolation level:** Khi chạy giao dịch tài chính/audit, luôn khai báo rõ mức độ cô lập (thông thường `read committed` hoặc `serializable` tùy nghiệp vụ).
- **Không dùng raw SQL trực tiếp rải rác:** Tuyệt đối không viết raw SQL (`sql` string literal của Drizzle) trực tiếp trong các services. Mọi câu lệnh raw SQL phức tạp (ví dụ truy vấn PostGIS nearby, ltree hierarchy) phải được gói trong các helper functions của Drizzle mapping layer, hoặc được đóng gói bên trong các custom methods của Repository. Điều này giúp dễ dàng thực hiện audit, profiling, và logging tập trung.
