# STEP 4.3.5 CLOSEOUT REPORT — MEDIA INGESTION ORCHESTRATION & SECURITY INTEGRATION

## 1. Mục tiêu
Hoàn thành tầng điều phối (Orchestration) và tích hợp HTTP endpoints cho Media Ingestion, bảo đảm các tiêu chuẩn nghiêm ngặt về bảo mật thông tin, bồi hoàn tài nguyên lỗi (compensation) và chặn tải lên dung lượng lớn tại cổng ingress.

---

## 2. Giải pháp Triển khai & Hardening

### A. Chỉ Chấp Nhận IMAGE & Chặn Video/Document
- Ném trực tiếp `UnsupportedMediaTypeError` ngay từ đầu hàm `ingest` nếu `mediaType !== 'IMAGE'`. Loại bỏ hoàn toàn luồng upload file thô chưa được kiểm duyệt.

### B. Bồi Hoàn Tài Nguyên Idempotent (Compensation)
- Các khoá lưu trữ `masterKey` và các `variantKey` được đẩy vào danh sách `uploadedKeys` **trước khi** bắt đầu gọi `storage.upload()`.
- Nhờ tính chất idempotent của phương thức `delete` trên storage adapter, các file tải lên dở dang bị lỗi timeout hoặc ngắt kết nối giữa chừng vẫn được dọn dẹp sạch sẽ khỏi Cloudinary.

### C. Bảo Toàn READY State
- Tích hợp cờ trạng thái `isFinalized = false` trong luồng xử lý. Trạng thái chuyển thành `true` ngay sau khi DB finalization READY commit thành công.
- Nếu bước đọc lại bản ghi READY (`findById`) gặp lỗi transient, hệ thống bọc lỗi an toàn trả về client mà không chạy các tác vụ xóa file hoặc hạ DB status thành `FAILED`.

### D. Giấu Lỗi Database / Cloudinary Nhạy Cảm
- Các lỗi database thô hay credentials bị log an toàn ở máy chủ và bọc thành `StorageUploadError('Failed to process and store media file')` trả về client với mã lỗi `500 MED_SYS_001`.

### E. Giới Hạn Payload Tải Lên Tại Ingress
- Sử dụng middleware `bodyLimit` của Hono cho endpoint `/upload` với giới hạn tối đa `10.5MB` để tạo overhead dung lượng cho boundaries/text fields, đồng thời service core vẫn validate chính xác `10MB` cho file buffer.

### F. Strict DTO Validation
- Controller bóc tách trường file và validate các text parameters còn lại bằng Zod strict schema. Mọi request chứa các trường cấm như `ownerType`, `ownerId` bị loại bỏ và trả về status `400 VAL_001`.
