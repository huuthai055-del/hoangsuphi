## 2. KẾT QUẢ RÀ SOÁT BLUEPRINTS (03.01.01 -> 03.01.09)

| Tài liệu | Trạng thái | Nội dung cốt lõi đã thống nhất |
|:---|:---:|:---|
| **03.01.01 — Domain Design** | ✅ Approved | Rich Domain Model (User, UserSession, UserProfile). Soft Delete. Brute Force lockout 15 phút. Tách biệt Identity và Authorization. |
| **03.01.02 — API Design** | ✅ Approved | Endpoints `/api/v1/auth/login`, `/api/v1/auth/refresh`, `/api/v1/auth/logout`, `/api/v1/users/me` (GET/PATCH). Response bọc trong `{ data }` chuẩn. |

| **03.01.05 — Repository Design** | ✅ Approved | Drizzle ORM + Postgres (Không cache Redis). JOIN tối ưu để nạp User + Profile. Giao dịch đa bảng (Transactions). |
| **03.01.06 — DTO & Validation** | ✅ Approved | Zod Schemas strict mode (`.strict()`) chống Mass Assignment. Email normalized. invalidParams cho RFC 7807 validation error. |
| **03.01.07 — Controller Design** | ✅ Approved | Thin Controllers. Dynamic Secure cookie (`Secure` theo env NODE_ENV). Router guards (authenticate + requirePermission). |
| **03.01.08 — Security Controls** | ✅ Approved | Bun native Bcrypt rounds = 12. HttpOnly Cookie SameSite=Strict. Rate limit login động theo IP. RBAC matrix 3 vai trò tĩnh. |
| **03.01.09 — Testing Strategy** | ✅ Approved | `bun test` + `hono/testing` RAM mock request. DB Transactions Rollback. 10 Core Test Cases. Coverage tập trung 100% nghiệp vụ chính. |

## 4. BEST PRACTICES CHO GIAI ĐOẠN LẬP TRÌNH (EXECUTION RULES)

1. **Tuân thủ Tuyệt đối Blueprint:** Đội ngũ lập trình không được tự ý thêm thắt biến, cột database, hoặc đổi tên phương thức ngoài các tài liệu đã chốt.
2. **Strict TypeScript:** Bật option `strict: true` trong `tsconfig.json`. Tuyệt đối cấm sử dụng kiểu `any` (sử dụng `unknown` hoặc ép kiểu tường minh nếu bắt buộc).
3. **Logging & Debugging Policy:** 
   - *Trong quá trình phát triển (Development):* Cho phép sử dụng `console.log` tạm thời để hỗ trợ gỡ lỗi nhanh. Tuyệt đối cấm commit các lệnh `console.log` này lên các nhánh chính (`main`, `release`).
   - *Trong môi trường vận hành (Production):* Tất cả các hoạt động log bắt buộc phải đi qua Pino Logger để đảm bảo cấu trúc JSON log thống nhất, kèm `traceId` và phân cấp Log Level rõ ràng.
