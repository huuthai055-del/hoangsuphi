## 1. MỤC TIÊU

Thiết kế chiến lược kiểm thử (Testing Strategy) tinh giản, thiết thực nhất cho **Identity Module** nhằm:
- Đảm bảo tính ổn định và chính xác của các use cases xác thực (login, refresh, logout) và thông tin cá nhân.
- Tập trung nguồn lực vào 3 lớp kiểm thử có giá trị thực tế cao nhất:
  - **Unit Test** cho Service Layer (Nơi chứa logic điều phối).
  - **Integration Test** cho Repository Layer (Xác thực câu lệnh SQL Drizzle chạy đúng trên PostgreSQL).
  - **API Test (HTTP Light Test)** cho Router/Endpoint (Kiểm soát response header/payload).
- Triển khai quy trình tự động hóa kiểm thử dễ chạy trên local bằng Bun native test runner (`bun test`), không cần cài đặt các thư viện test runner cồng kềnh (như Jest hay Mocha).
- Tiết kiệm thời gian bằng việc loại bỏ stress test, load test hay E2E GUI test phức tạp trong giai đoạn MVP cấp huyện này.

### 2.1 Unit Test (Service Layer)

- **Mục tiêu:** Kiểm thử toàn bộ các nhánh logic của `AuthService` và `UsersService` mà không cần kết nối Database thật.
- **Thực thi:** Sử dụng tính năng mock tích hợp của Bun (`mock` helper) để giả lập hành vi của `IUserRepository`, `ISessionRepository` và `ITokenService`.
- **Ví dụ viết test: `apps/backend/src/modules/auth/service/auth.service.test.ts`**
```typescript
import { describe, test, expect, mock, beforeEach } from 'bun:test'
import { AuthService } from './auth.service'
import { IUserRepository } from '@/modules/users/repository/user-repository.interface'
import { ISessionRepository } from '../repository/session-repository.interface'
import { ITokenService } from '@/lib/auth/token-service.interface'
import { AuthenticationError } from '@/common/errors/http.errors'

describe('AuthService - Unit Tests', () => {
  let authService: AuthService
  let mockUserRepo: IUserRepository
  let mockSessionRepo: ISessionRepository
  let mockTokenService: ITokenService

  beforeEach(() => {
    // Giả lập Mock interfaces bằng Bun mock
    mockUserRepo = {
      findById: mock(() => Promise.resolve(null)),
      findByEmail: mock(() => Promise.resolve(null)),
      save: mock(() => Promise.resolve())
    }
    
    mockSessionRepo = {
      findById: mock(() => Promise.resolve(null)),
      findByTokenHash: mock(() => Promise.resolve(null)),
      save: mock(() => Promise.resolve()),
      revokeSession: mock(() => Promise.resolve())
    }

    mockTokenService = {
      generateAccessToken: mock(() => Promise.resolve('mock_access_token')),
      generateRefreshToken: mock(() => Promise.resolve('mock_refresh_token')),
      verifyAccessToken: mock(() => Promise.resolve({} as any)),
      verifyRefreshToken: mock(() => Promise.resolve({ sessionId: 'session_123' }))
    }

    authService = new AuthService(mockUserRepo, mockSessionRepo, mockTokenService)
  })

  test('login() - should throw AuthenticationError if email not found', async () => {
    mockUserRepo.findByEmail = mock(() => Promise.resolve(null)) // Email không tồn tại

    expect(
      authService.login({
        email: 'notfound@hoangsuphi.vn',
        password: 'password123',
        deviceId: 'c8b35f28-090c-4e86-a212-32a2c07466fa'
      }, { ipAddress: '127.0.0.1', userAgent: 'BunTest' })
    ).rejects.toThrow(AuthenticationError)
  })
})
```

### 2.2 Integration Test (Repository Layer)

- **Mục tiêu:** Xác nhận các câu lệnh Drizzle ORM (`select`, `innerJoin`, `onConflictDoUpdate`) tương tác đúng cấu trúc bảng thực tế của PostgreSQL.
- **Thực thi:**
  - Chạy PostgreSQL container thông qua Docker Compose (đã thiết lập ở `02.03`).
  - Sử dụng database test độc lập (ví dụ: `hoangsuphi_test`).
  - Trước mỗi test file: chạy migration để chuẩn hóa bảng.
  - Mỗi test case chạy trong một PostgreSQL Transaction và tự động **ROLLBACK** ở cuối test để đảm bảo môi trường database luôn sạch (không bị ô nhiễm dữ liệu chéo giữa các test).

### 2.3 API Test (HTTP Light Test)

- **Mục tiêu:** Đảm bảo Router cấu hình đúng middleware, bắt lỗi validate Zod chính xác và định cấu hình response headers/Set-Cookie chuẩn.
- **Thực thi:** Sử dụng helper `app.request()` của Hono.js. Đây là giải pháp mô phỏng request cực nhanh trực tiếp trên bộ nhớ RAM, chạy test mà không cần khởi động HTTP port lắng nghe thật.
- **Ví dụ viết test: `apps/backend/src/modules/auth/route/auth.route.test.ts`**
```typescript
import { describe, test, expect } from 'bun:test'
import { authRoute } from './auth.route'

describe('Auth Router - API Tests', () => {
  test('POST /login - should return 400 when body input is invalid', async () => {
    // Gửi request thiếu password và deviceId
    const res = await authRoute.request('/login', {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json'
      },
      body: JSON.stringify({
        email: 'invalid-email-format'
      })
    })

    expect(res.status).toBe(400)
    const json = await res.json()
    expect(json.code).toBe('VAL_001') // Mã lỗi validate tiêu chuẩn RFC 7807
    expect(json.invalidParams.length).toBe(3) // Lỗi email format, thiếu pwd, thiếu deviceId
  })
})
```

---
- **Test Coverage Policy (Chính sách độ bao phủ thực tế):**
  - **Không** đặt mục tiêu đạt 100% coverage cho toàn bộ dự án.
  - **Bắt buộc** đạt **100% coverage** cho các nghiệp vụ cốt lõi:
    - Login / Refresh / Logout logic.
    - Token validation / Authorization guards.
    - DTO Validation schemas.
  - Các thành phần thuần túy như DTO types, data mappers, database schemas không ép chỉ số này để tránh lãng phí nguồn lực viết test vô nghĩa.

## 4. BEST PRACTICES

- **No Flaky Tests:** Mỗi test case phải tự cô lập dữ liệu (Hermetic testing). Không viết code test dựa trên giả định rằng test case trước đó đã insert sẵn dữ liệu.
- **Mock External Interfaces only:** Chỉ mock các cổng kết nối ngoại vi (Repositories, Token Generator). Không bao giờ mock Domain Entities (`User`, `UserSession`) vì domain logic cần được thực thi thật để kiểm thử độ chính xác của nghiệp vụ.
- **Run fast:** Tận dụng `bun test` cho tốc độ khởi động cực nhanh (<1 giây), giúp tích hợp CI/CD mượt mà sau này.
