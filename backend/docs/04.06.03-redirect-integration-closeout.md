# Phase 4.6 — Redirect Management Closeout

**Status:** 🔒 LOCKED on 2026-07-19 after explicit user authorization and final acceptance verification.

## Delivered scope

- Backend is the source of truth for an internal-path-only redirect registry, protected admin CRUD, and a read-only public resolver.
- The additive `0018_redirect_registry` migration is present in a contiguous Drizzle journal and is applied successfully to the dedicated PostgreSQL test database.
- Redirect rules allow only `301` and `302`, canonicalize lowercase/NFC/no-trailing-slash paths, discard query strings at resolution, and reject external, wildcard, self, chain, cycle, API, framework, sitemap, robots, favicon, and static-image sources.
- Redis resolver cache uses a 60-second TTL and is invalidated/repopulated correctly after create, update, and delete.
- Next.js middleware performs only public `GET`/`HEAD` redirects, emits a one-hop `308` for case/trailing-slash canonicalization, passes through backend `301`/`302`, strips query strings for registry redirects, and fails open when the resolver is unavailable.
- Resolver responses are validated before execution. Non-canonical, system, malformed, unsupported-status, or self-loop targets cannot become browser redirects.
