## 1. DOCKER COMPOSE & DEVELOPMENT ENVIRONMENT

---

### 1.1 Mục tiêu

- **Nhất quán môi trường (Environment Consistency):** Đảm bảo mọi thành viên trong dự án và hệ thống CI/CD chạy cùng một phiên bản chính xác của PostgreSQL (với các extensions bắt buộc), Redis, và Typesense.
- **Khởi động một dòng lệnh:** Chỉ cần chạy `docker compose up -d` là sẵn sàng toàn bộ hạ tầng phát triển cục bộ (Local Dev Stack).
- **Tự động cấu hình (Auto-provisioning):** Cơ sở dữ liệu tự động kích hoạt các extensions (`postgis`, `ltree`, `pg_uuidv7`) ngay khi container khởi tạo lần đầu.
- **Giám sát sức khỏe (Healthcheck):** Các service trong docker compose tự kiểm tra sức khỏe, đảm bảo ứng dụng backend chỉ kết nối khi DB và Redis thực sự sẵn sàng.
- **Persist dữ liệu:** Tránh mất mát dữ liệu khi container bị tắt hoặc build lại.

---

### 1.2 Thiết kế

Chúng ta sử dụng một tệp `docker-compose.yml` ở thư mục gốc để quản lý toàn bộ stack hạ tầng phát triển cục bộ.

#### `docker-compose.yml` (Root)

```yaml
version: '3.8'

services:
  # ============================================================
  # POSTGRESQL (Primary Database with Spatial & Tree extensions)
  # ============================================================
  postgres:
    image: postgis/postgis:16-3.4
    container_name: hsp_postgres_dev
    environment:
      POSTGRES_USER: hsp_user
      POSTGRES_PASSWORD: hsp_password
      POSTGRES_DB: hsp_db
      PGDATA: /var/lib/postgresql/data/pgdata
    ports:
      - "5432:5432"
    volumes:
      - hsp_postgres_data:/var/lib/postgresql/data
      # Mount thư mục init để tự động cài đặt extensions
      - ./docker/postgres/init:/docker-entrypoint-initdb.d
    networks:
      - hsp_network
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U hsp_user -d hsp_db"]
      interval: 5s
      timeout: 5s
      retries: 5
    restart: unless-stopped

  # ============================================================
  # REDIS (Caching, Session, Queue, Rate Limiting)
  # ============================================================
  redis:
    image: redis:7.2-alpine
    container_name: hsp_redis_dev
    command: redis-server --requirepass hsp_redis_password --appendonly yes
    ports:
      - "6379:6379"
    volumes:
      - hsp_redis_data:/data
    networks:
      - hsp_network
    healthcheck:
      test: ["CMD", "redis-cli", "-a", "hsp_redis_password", "ping"]
      interval: 5s
      timeout: 3s
      retries: 5
    restart: unless-stopped

  # ============================================================
  # TYPESENSE (Full-text & Vector Search Engine)
  # ============================================================
  typesense:
    image: typesense/typesense:0.25.2
    container_name: hsp_typesense_dev
    environment:
      TYPESENSE_API_KEY: hsp_typesense_api_key
      TYPESENSE_DATA_DIR: /data
    ports:
      - "8108:8108"
    volumes:
      - hsp_typesense_data:/data
    networks:
      - hsp_network
    healthcheck:
      test: ["CMD", "curl", "-f", "http://localhost:8108/health"]
      interval: 5s
      timeout: 3s
      retries: 5
    restart: unless-stopped

networks:
  hsp_network:
    name: hsp_network_dev
    driver: bridge

volumes:
  hsp_postgres_data:
    name: hsp_postgres_data_dev
  hsp_redis_data:
    name: hsp_redis_data_dev
  hsp_typesense_data:
    name: hsp_typesense_data_dev
```

#### SQL Init script: `docker/postgres/init/00_extensions.sql`

Tự động hóa việc tạo PostgreSQL extensions.

```sql
-- Kích hoạt các extension cần thiết cho dự án
CREATE EXTENSION IF NOT EXISTS "uuid-ossp";
CREATE EXTENSION IF NOT EXISTS "postgis";
CREATE EXTENSION IF NOT EXISTS "ltree";

-- Setup pg_uuidv7 (nếu dùng thư viện ngoài) hoặc chuẩn bị schema cho application generation.
-- Vì PostgreSQL 16 chưa hỗ trợ native uuid_generate_v7, ứng dụng sẽ sinh UUIDv7 ở tầng Application.
-- Tuy nhiên, nếu cần tối ưu hiệu năng gen key tại DB khi raw insert, ta có thể cài extension hoặc PL/pgSQL helper.
-- Dưới đây là PL/pgSQL helper để generate UUIDv7 cho các scripts seed/migration tại DB:
CREATE OR REPLACE FUNCTION uuid_generate_v7()
RETURNS uuid AS $$
DECLARE
  unix_time_ms bytea;
  uuid_bytes bytea;
BEGIN
  -- Lấy timestamp hiện tại (miliseconds)
  unix_time_ms := substring(decode(lpad(to_hex(floor(extract(epoch from clock_timestamp()) * 1000)::bigint), 16, '0'), 'hex') from 3 for 6);
  
  -- Generate 10 bytes random
  uuid_bytes := unix_time_ms || gen_random_bytes(10);
  
  -- Set phiên bản (version 7) -> 4 bits đầu của byte thứ 7 là 0111 (0x70)
  uuid_bytes := set_byte(uuid_bytes, 6, (get_byte(uuid_bytes, 6) & 15) | 112);
  
  -- Set biến thể (variant 1) -> 2 bits đầu của byte thứ 9 là 10 (0x80)
  uuid_bytes := set_byte(uuid_bytes, 8, (get_byte(uuid_bytes, 8) & 63) | 128);
  
  RETURN encode(uuid_bytes, 'hex')::uuid;
END;
$$ LANGUAGE plpgsql VOLATILE;
```

### 1.3 Lý do lựa chọn

| Thành phần | Công nghệ lựa chọn | Lý do |
|:---|:---|:---|
| **Base PostgreSQL Image** | `postgis/postgis:16-3.4` | Chứa sẵn PostGIS extension được build chuẩn hóa, tránh việc tự cài trên alpine mất thời gian compile C/C++ libs. |
| **Redis Image** | `redis:7.2-alpine` | Nhỏ gọn, tối ưu tài nguyên, có alpine security updates nhanh chóng. |
| **Typesense version** | `0.25.2` | Phiên bản LTS ổn định, hiệu năng cao hơn Elasticsearch/OpenSearch từ 5-10x ở tài nguyên giới hạn. |
| **Healthchecks** | `pg_isready` & `redis-cli ping` | Tránh việc backend cố kết nối khi container đang boot up dẫn đến crash khởi động. |
| **PL/pgSQL UUIDv7** | Custom function | Giải quyết vấn đề PostgreSQL 16 chưa hỗ trợ native UUIDv7 mà không cần bắt buộc cài extension C (vốn phức tạp trên môi trường managed DB Cloud sau này). |

### 1.4 Ưu điểm

- **Tự động hóa hoàn toàn (Zero configuration):** Clone dự án, cài Docker, chạy lệnh là có thể bắt đầu code.
- **Isolation:** Không cần cài đặt PostgreSQL hay Redis trực tiếp trên máy chủ vật lý, tránh xung đột cổng hoặc version.
- **Tốc độ:** Khởi động và dọn dẹp môi trường thử nghiệm cực nhanh trong CI/CD pipeline.
- **Sẵn sàng sản xuất (Production-ready alignment):** Các service cấu hình sát với môi trường Production, giảm thiểu lỗi "chạy được trên máy dev nhưng lỗi trên staging".

---

### 1.5 Nhược điểm

- **Tốn tài nguyên cục bộ:** Chạy đồng thời 3 container chiếm khoảng 500MB-1GB RAM máy dev.
- **Cảnh báo bảo mật Docker Desktop:** Trên Windows, việc đồng bộ file có thể chậm nếu không dùng WSL2.

### 1.6 Các lựa chọn khác đã xem xét

| Phương án | Mô tả |
|:---|:---|
| **Local installation (Bare metal)** | Cài đặt trực tiếp PG, Redis lên Windows/macOS. |
| **Cloud-managed Services (Supabase/Aiven)** | Dùng DB/Redis Cloud miễn phí để phát triển. |
| **Docker Compose chứa cả app backend** | Đóng gói cả Bun app backend vào Docker Compose để dev. |

---

### 1.7 Vì sao không chọn

- **Local installation:** Cực kỳ khó quản lý phiên bản thống nhất giữa các developer (người dùng Mac dùng Homebrew cài PG17, người dùng Windows dùng installer cài PG16, dẫn đến khác biệt về ltree/PostGIS behavior).
- **Cloud-managed Services:** Phụ thuộc vào kết nối Internet, độ trễ mạng cao hơn local loopback (10-50ms so với <1ms), và tốn chi phí/giới hạn quota.
- **Docker Compose chứa backend app:** Khiến tốc độ reload code (Hot Module Replacement) của Bun bị giảm do IO overhead qua Docker volume mount. Tốt nhất là hạ tầng chạy trong Docker, backend app (Bun) chạy trực tiếp trên host machine kết nối vào Docker ports.

### 1.8 Khả năng mở rộng

- **Phase 4 (Analytics & Sync):** Dễ dàng cắm thêm các container của **Debezium**, **Kafka** (hoặc Redpanda) và **ClickHouse** vào cùng tệp compose hoặc tệp override `docker-compose.analytics.yml`.
- **Mở rộng môi trường:** Sử dụng `docker-compose.prod.yml` để override cấu trúc mạng, ẩn các cổng DB/Redis khỏi internet và bật chế độ Cluster/Sentinel cho Redis.

---

### 1.9 Best Practices

- **Named Volumes:** Sử dụng named volumes (`hsp_postgres_data_dev`) thay vì bind mounts trực tiếp thư mục để tối ưu tốc độ I/O trên macOS/Windows.
- **Mạng riêng biệt (Bridge Network):** Tất cả container nằm chung một mạng isolated, không dùng mặc định bridge network của Docker để tránh xung đột IP và tăng khả năng phân giải DNS nội bộ.
- **Bảo mật tối thiểu ở dev:** Vẫn sử dụng mật khẩu (`hsp_password`, `hsp_redis_password`) để ứng dụng làm quen với việc xử lý connection string có credentials.
