## 2. Design & Implementation Details

### 2.1 HTTP Query DTO & Schema Validation
Implemented in [nearby.dto.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/modules/nearby/dto/nearby.dto.ts):
- `nearbySearchQuerySchema` defines the query contract using Zod's `.strict()` mode to reject unknown query parameters.
- Rejects empty values, out-of-range limits, and scientific notation formats (e.g. `e` / `E`).
- **CSV Types Parsing:** The `types` field supports comma-separated values (e.g., `place,attraction`) and enforces strict syntax checks:
  - Rejects double commas (`,,`), leading commas (`,types`), or trailing commas (`types,`).
  - Restricts values to the allowlisted enums (`place`, `attraction`, `business`, `utility`).
  - Rejects duplicates or altered-casing values.
- **Repeated Parameters Guard:** Employs the `normalizeRawQueryInput` utility to parse `URLSearchParams`. Repeated keys (e.g. `lat=22.7&lat=23.0`) are parsed as string arrays instead of being silently collapsed, causing Zod schema validation to fail with a validation exception (`VAL_001`).

### 2.2 Response Mapping & Attribute Protection
Implemented in [nearby-response.mapper.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/modules/nearby/http/nearby-response.mapper.ts):
- Maps `NearbySearchResult` returned by the service layer to the public `NearbyResponseDto` envelope.
- Enforces strict compile-time types preventing the leakage of internal database attributes such as `rawDistanceMeters` or `entityTypeRank`.
- Public response format details:
  - `distanceMeters`: rounded to two decimal places (computed in the service layer).
  - `rating`: holds count and average fields.
  - `pagination`: returns a base64url opaque cursor or null.
  - Empty search page returns `200 OK` with an empty data array instead of `404 Not Found`.

### 2.3 Controller & Route Integration
- **NearbyController** ([nearby.controller.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/modules/nearby/http/nearby.controller.ts)):
  - Acts as a thin HTTP-adapter.
  - Extracts the parsed `validQuery` from Hono Context, calls `NearbySearchService.search`, and delegates public formatting to `mapNearbySearchResponse`.
  - Free from repository connections, cursor signing, range validation, or default values logic.
- **Router mounting** ([nearby.routes.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/modules/nearby/http/nearby.routes.ts) and [register-routes.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/app/register-routes.ts)):
  - Mounts `GET /api/v1/nearby` route under Hono v1Router.
  - Applies `validateNearbyQuery` middleware to enforce DTO compliance.
  - Set as a public API path without authentication requirements.

### 2.4 Dependency Injection Configuration
Registered in [container.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/common/di/container.ts):
- `'NearbyRepository'` (injects `DrizzleNearbyRepository` with database client `db`)
- `'NearbyCursorCodec'` (injects `NearbyCursorCodec` using active keyring keys)
- `'NearbySearchService'` (injects `NearbySearchService` with repository and cursor codec resolved instances)
- `'NearbyController'` (injects `NearbyController` with search service resolved instance)

### 2.5 RFC 7807 Error Serialization
Validation errors or invalid cursor payloads thrown from the application layers automatically bubble up to Hono's global `errorHandlerMiddleware`, returning:
- `400 Bad Request` status code.
- `VAL_001` error code.
- `invalidParams` details map.
- Server-side database or configuration errors return a generic `500 Internal Server Error` without leaking stack traces or internal configuration secrets.
