## 2. Design & Implementation Details

### 2.1 Application Input & Normalized Criteria
Implemented in [nearby-search.types.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/modules/nearby/application/nearby-search.types.ts):
- `NearbySearchInput` accepts raw input types independent of HTTP Context.
- Normalizes coordinates, limits, and optional fields into criteria.
- Defaults: `radiusMeters = 5000`, `limit = 20`, `entityTypes` = all 4 canonical branches.

### 2.2 Coordinate Normalization & Precision
- Checks that coordinate values are not empty and do not contain scientific notation (e.g. `e` / `E`).
- Restricts precision to at most 6 decimal places (fractional part length check).
- Normalizes negative zero `-0` to `"0.000000"` to prevent query mismatch issues.
- Converts numbers/strings into canonical string formats with exactly 6 decimal places (using `toFixed(6)` on clean values).

### 2.3 Entity Type Rank Normalization
- Entity types mapped to internal branches (`TOURIST_PLACE`, `ATTRACTION`, `BUSINESS`, `UTILITY`).
- Restricts inputs to allowlisted types (`place`, `attraction`, `business`, `utility`).
- Sorts branch list canonically by entity ranking:
  1. `TOURIST_PLACE`
  2. `ATTRACTION`
  3. `BUSINESS`
  4. `UTILITY`
- Duplicates are rejected with validation errors rather than silently deduplicated.

### 2.4 Category Taxonomy Validation
- Enforces cross-field validations: If `categoryId` is provided, `entityTypes` must be explicitly defined, must contain exactly one type, and cannot be `TOURIST_PLACE`.

### 2.5 Canonical Query & Fingerprint
Implemented in [nearby-query-fingerprint.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/modules/nearby/application/nearby-query-fingerprint.ts):
- Serializes canonical properties deterministically with fixed key ordering (`lat`, `lng`, `radius`, `types`, `regionId`, `categoryId`, `minRating`, `limit`, `sort`).
- Generates `SHA-256` lowercase hex fingerprints of the canonical JSON string.
- Ensures equivalent requests yield matching fingerprints, while differing contexts yield unique fingerprints.

### 2.6 signed HMAC-SHA256 Cursor Codec
Implemented in [nearby-cursor.codec.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/modules/nearby/application/nearby-cursor.codec.ts):
- Payload shape constraints: `v: 1` version, key ID `kid`, SHA-256 fingerprint `fp`, and `key` object containing `distance: string` (raw unrounded distance), `entityType`, and `id` (UUID).
- Employs base64url serialization envelopes.
- signs payloads using `HMAC-SHA256` keys loaded from the config keyring.
- Verifies signatures using timing-safe comparisons (`timingSafeEqual`) to prevent timing side-channel attacks.
- Gracefully handles key rotation by allowing previous keys to decode while active keys sign.

### 2.7 Application Errors Classification
Defined in [nearby-application.errors.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/modules/nearby/application/nearby-application.errors.ts):
- `NearbyValidationError`: General input validation errors.
- `InvalidNearbyCursorError`: Thrown when signatures fail, structures are malformed, or keyrings are invalid.
- `UnsupportedNearbyCursorVersionError`: Thrown on mismatched version fields (`v !== 1`).
- `NearbyCursorQueryMismatchError`: Thrown when fingerprints mismatch.
- `NearbyCursorConfigurationError`: Server-side keyring configuration issues.

## 4. Security Audit Compliance

- **Secrets Management:** Loaded signing key ID and secrets securely from environment configuration keyring with proper fallback namespaces, avoiding hard-coded constants.
- **Timing Attacks Defense:** HMAC verification checks are implemented with timing-safe buffers comparison (`timingSafeEqual`), protecting against timing analysis.
- **Safe JSON Deserialization:** Envelope validation utilizes strict structural check guards before evaluating fields, avoiding prototype pollution.
- **Cursor Length Limit:** Restricts incoming cursor string length to a maximum of 512 characters.
- **Logs Sanitation:** Excluded full raw cursor bodies, active secrets, and exact coordinates from application trace logs.

---

## 5. Scope Compliance Verification

- **No HTTP Layer Integration:** No Hono controller, endpoints, or routes defined.
- **No SQL modifications:** Handled validation and mappings at the application service tier, invoking `INearbyRepository` cleanly without modifying queries.
- **No Schema / Migration Changes:** Kept database schema unchanged.

## 6. Implementation Notes for Step 4.2.4

1. **HTTP Endpoint Routing:** The router in `nearby.route.ts` will parse query parameter strings (lat, lng, radius, types, regionId, categoryId, minRating, limit, cursor) and pass them as a clean `NearbySearchInput` object to `NearbySearchService.search`.
2. **Exception Mapping:** The route controller will register the global error boundary mapping of `NearbyValidationError`, `InvalidNearbyCursorError`, `UnsupportedNearbyCursorVersionError`, and `NearbyCursorQueryMismatchError` to RFC 7807 formatted HTTP 400 Bad Request responses containing localized details.
3. **DI Registration:** `NearbySearchService` and `NearbyCursorCodec` will be registered in Hono's dependency injection container, resolving concrete repository and keyring configurations.
