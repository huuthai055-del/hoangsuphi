## 4. Implementation summary
- **Email Foundation**: Đã hoàn thiện thiết kế `IEmailSender` abstraction, đảm bảo độc lập với nhà cung cấp. `FakeEmailSender` hỗ trợ kiểm thử timeout và provider errors.
- **Verify Email**: Đã tích hợp luồng đăng ký (tạo `pending_verification`), cấp phát token 24 giờ, resend token chống enumeration, xác thực atomic.
- **Forgot/Reset**: Request token 30 phút, chống enumeration, reset atomic, revoke toàn bộ session và refresh token trên toàn hệ thống sau khi reset.
- **Contact Form**: Form an toàn, escape HTML, chống Header Injection, rate limit 5 reqs/IP/hour, gửi cả nội dung HTML và plain text.

## 5. API manifest
- `POST /api/v1/auth/email-verification/resend`: Resend verify email, rate limit 10/IP/h, 3/email/h.
- `POST /api/v1/auth/email-verification/confirm`: Confirm token.
- `POST /api/v1/auth/password/forgot`: Request reset token, rate limit 10/IP/h, 3/email/h.
- `POST /api/v1/auth/password/reset`: Đặt lại mật khẩu.
- `POST /api/v1/contact`: Submit contact form, rate limit 5/IP/h.

## 6. Token audit
- **Entropy**: 32 bytes (`crypto.randomBytes(32)`).
- **Encoding**: base64url.
- **Hash**: SHA-256 (lưu trữ DB).
- **TTL**: 24h cho verify, 30 phút cho reset.
- **One-time**: Tiêu thụ atomic bằng `update ... returning` với mệnh đề `expiresAt > now()`.
- **Revocation**: Đè token cũ bằng supersede logic.
- **Concurrency**: Đảm bảo an toàn không race condition.

## 7. Enumeration audit
- Các request `resend` và `forgot` trả về 202 không đổi dù email tồn tại hay không, hoặc status tài khoản ra sao. Fake delay / Dummy rendering được sử dụng để cân bằng timing attack (đã pass test).

## 8. Session revocation audit
- Mọi password reset đều có bước xóa bản ghi trong bảng `sessions` và `refresh_tokens` thuộc user id đó trong một Transaction PostgreSQL duy nhất.

## 9. Contact Form audit
- Validation: Rất nghiêm ngặt qua Zod (không CR/LF).
- Header injection: Bị chặn.
- HTML escaping: Escaped cho mọi dữ liệu input.
- Plain text: Có version plain text.
- Recipient: Truy xuất từ biến môi trường, client không thể can thiệp.
- Tự động Reply: Không cấu hình tự động reply (để tránh spam reputation).
- Persistence: Hoàn toàn không lưu database.

## 10. Email provider audit

- Automation test pass bằng provider giả lập, không sử dụng key thật.
- `ResendEmailSender` chưa được cài đặt vì thuộc Step 4.5.6 sau khi domain được xác minh; do đó không có Resend adapter mock-HTTP test để tuyên bố PASS trong Step 4.5.5.
