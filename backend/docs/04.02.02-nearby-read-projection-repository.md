## 3. SQL Architecture & Unified Query

All entity branches are composed in a single query client execution inside [nearby.repository.ts](file:///c:/Users/tony/Desktop/youtube/hoangsuphi/backend/src/modules/nearby/repository/nearby.repository.ts):
1. **Origin CTE:** Combines inputs into a single geography point:
   ```sql
   "origin" AS (
     SELECT ST_SetSRID(ST_MakePoint(:longitude, :latitude), 4326)::geography AS "point"
   )
   ```
2. **Ratings CTE:** Aggregates approved, non-deleted reviews by owner type:
   ```sql
   "nearby_ratings" AS (
     SELECT
       owner_type::public.owner_type AS "owner_type",
       owner_id AS "owner_id",
       AVG(rating::numeric) AS "raw_rating",
       COUNT(id)::integer AS "review_count"
     FROM reviews
     WHERE status = 'APPROVED'::public.review_status AND deleted_at IS NULL
     GROUP BY owner_type, owner_id
   )
   ```
3. **UNION ALL Composition (Subquery-Optimized):** Selects from nested subqueries for each branch. By computing `ST_Distance(location, origin.point, true)` exactly once inside the inner query and aliasing it to `distanceMeters`, the outer selection of that branch projects it as both `rawDistanceMeters` (by casting `::text`) and `distanceMeters` (as float/double precision). This avoids duplicate PostGIS WGS84 spheroid calculations per row.
4. **Visibility Checks:** Filters active/non-deleted entries and checks parent region visibility by inner joining `regions` and verifying `regions.deleted_at IS NULL`.
5. **Taxonomy & Category Filters:** Matches Attraction/Utility by `is_utility` category flags, and Business by active business types, resolving mismatches correctly in SQL (yielding empty data instead of 400 validation error).

## 4. Keyset Pagination & Ordering

Sorting is globally stable:
```sql
ORDER BY "distanceMeters" ASC, "entityTypeRank" ASC, "entityId" ASC
```
Where rank maps to:
- `1` = `TOURIST_PLACE`
- `2` = `ATTRACTION`
- `3` = `BUSINESS`
- `4` = `UTILITY`

The Keyset boundary comparison utilizes double-precision floats for distance and PostgreSQL UUID types:
```sql
(
  "distanceMeters" > :distance::double precision
  OR (
    "distanceMeters" = :distance::double precision
    AND "entityTypeRank" > :rank::integer
  )
  OR (
    "distanceMeters" = :distance::double precision
    AND "entityTypeRank" = :rank::integer
    AND "entityId" > :uuid::uuid
  )
)
```
